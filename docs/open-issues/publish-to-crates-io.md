# No crate is published to crates.io

## Summary

`goal@rootpoint@real-presentations` admits that the tool may be published later. Every crate is
`publish = false`, and none has a page for crates.io.

## Details

### What

Publishing gives each published crate a `CRATES-IO.md` page, as
`skill@knowledge-architect-setup@rust-project` proposes, a version scheme and the metadata
crates.io asks for.

### Why it matters

None while no program but rootpoint's own builds on its crates: no one else can install them from
crates.io, and the browser build that GitHub Pages serves needs no install. The owner named
publishing to crates.io as probable later, if the tool works out well. A published crate has
callers outside the project, which `design@rootpoint@grammar-and-api-stay-free` does not serve,
`issue@rootpoint@grammar-and-api-compatibility`.

### What would close it

The owner's word to publish, then the pages, the metadata and a first release; or the owner's
word that the tool stays unpublished.
